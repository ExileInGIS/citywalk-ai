## 二、方法与实测偏差（重要）

### 2.1 原计划：中文维基百科 Action API

计划使用的地址：

```
https://zh.wikipedia.org/w/api.php?action=query&prop=coordinates|extracts&exintro=1&explaintext=1&titles=...&format=json&redirects=1
```

### 2.2 实测：维基百科及其周边全部不可达

本次会话只能通过 `web_fetch` 访问外网（shell 无外网，已实测：`Invoke-WebRequest` 返回「基础连接已经关闭」）。逐个实测结果：

| 来源 | 结果 | 证据 |
| --- | --- | --- |
| `zh.wikipedia.org`（`/w/api.php` 与 `/wiki/` 两种路径） | 不可达 | `web_fetch` 多次返回 `TypeError: fetch failed` |
| `en.wikipedia.org` Action API | 不可达 | 同上 |
| `www.wikipedia.org` | 不可达 | 同上 |
| `api.wikimedia.org`（REST） | 不可达 | 同上 |
| `www.wikidata.org`（`wbsearchentities`） | 不可达 | 同上 |
| `zh.dbpedia.org`（维基简介的中文镜像） | 不可达 | `getaddrinfo ENOTFOUND` |
| `web.archive.org`（维基存档页） | 不可达 | `TypeError: fetch failed` |
| `www.openstreetmap.org`（对象页面） | 不可达 | `TypeError: fetch failed` |
| `nominatim.openstreetmap.org` | 不可达 | `TypeError: fetch failed` |
| 公共 CORS 代理（allorigins、codetabs）代取维基 | 失败 | HTTP 520 / 522 |
| `baike.baidu.com` | 拒绝服务 | HTTP 403，页面为「百度安全验证」 |
| `baike.sogou.com` | 可连但无正文 | HTTP 200，正文由 JS 渲染，抓到空内容 |
| `you.ctrip.com` | 可达 | HTTP 200，但 POI 详情页需逐个定位 ID |
| `wlj.nanjing.gov.cn`（南京市文旅局） | 可达 | HTTP 200，站点为资讯/政务栏目，没有逐 POI 的坐标页 |
| **`photon.komoot.io`（OSM 地理编码）** | **可达** | HTTP 200，返回含 `osm_type`/`osm_id`/标签/范围的 GeoJSON |
| **`baike.so.com`（360百科）** | **可达** | HTTP 200，服务端渲染正文 |

结论：**没有任何一条路径能取得维基百科的坐标或简介原文**。因此本次不使用维基数据，也不伪造「维基简介」。

### 2.3 实际采用的两类来源

1. **坐标 —— OpenStreetMap（经 Photon API 查询）**
   Photon 返回的是 OSM 对象的 GeoJSON，含 `osm_type`（node/way/relation）、`osm_id`、OSM 标签与 `extent`（要素范围）。因此每条坐标都能指回一个确定的 OSM 对象，可复核、可迁移、开源可再用（ODbL）。
   取点规则：优先取与地点名称/类型完全匹配的**面要素中心点**；没有面要素时，取最能代表该地点的点要素，并在 `notes` 里写清楚「这个点代表什么、不代表什么」。

2. **中文介绍 —— 360百科（含 1 条纯 OSM 推导）**
   8 个真实地点中：2 条为 360百科正文首段的**逐字摘录**（玄武湖、老门东），5 条为**要点转述**（颐和路、先锋书店、新街口、1912、夫子庙），1 条（白鹭洲公园）**没有取得介绍原文**，`extract` 是由 OSM 标签推导的描述文字。
   每条记录都用 `extractType` 标明属于哪一种，不混用。

### 2.4 没做的事

- 没有用任何「记忆中的经纬度」。所有经纬度都能在 `poi-enrichment.json` 里找到对应的 OSM 对象与 Photon 查询 URL。
- 没有用「附近任意一家门店」去顶替 4 个示例地点。
- 没有为示例地点编造营业时间。营业时间只在来源页面明确写出时才填（本次仅 2 条）。

### 3.2 三条需要解释的置信度

- **`p_book_xf`（medium）**：同一地点跨源偏差约 500 米。检索结果里的 Apple 地图门店页写 32.050720, 118.773496；OSM 节点写 32.0527745, 118.7682621。采用 OSM 值，是因为该节点自带门牌号「广州路 173 号」，与已知地址吻合。**上线前必须用高德/百度 POI 复核。**
- **`p_xuanwu`（medium）**：产品地点是「环湖步道」，OSM 坐标是**湖面**的中心点，不是步道上的点。词条记载湖岸周长约 15 公里，所以这个点只能代表「玄武湖景区中心」。真实导航应按入口（玄武门、解放门、太平门等）另取点。
- **`p_qinhuai`（medium）**：OSM 的「夫子庙」是 `leisure=park` 面要素，范围 118.7775–118.7897E、32.0151–32.0257N，东缘已接近白鹭洲公园，可能把周边绿地一并包含；坐标是面中心，不是孔庙大成殿门牌。另：秦淮河本身是河（relation/19289657），整条河的中心点在城南 31.9694N，离夫子庙段很远，**不能**用河流中心点代表「秦淮河畔」，故未采用。

## 四、4 个示例/泛化地点：必须由产品侧决定

这 4 条**没有单一实体**，坐标保持 `null`，并已在 JSON 中标记 `status: "generic-no-entity"`。按要求**没有**用附近任意门店冒充。

| id | 名称 | 为什么不能给坐标 | 建议的处理方向 |
| --- | --- | --- | --- |
| `p_cafe_sh` | 上海路街角咖啡馆 | 「上海路一带的街角咖啡馆」是一种类型，不是一个店 | 要么按「上海路」地理编码到路段（明确是路段不是店），要么从供应商 POI 里挑真实门店并改掉名称 |
| `p_book_tg` | 陶谷新村旧书店 | 「陶谷新村一带的小书店」是街区形态，没有对应实体 | 同上；陶谷新村本身是地名，可作「街区」对象 |
| `p_food_ld` | 老门东本地小馆 | 「街区内的小吃与简餐」是餐饮类型 | 若要真实 POI，需新增具体店铺并逐条核验营业时间与人均 |
| `p_market` | 城市露台市集 | 市集是**不定期活动**，不是固定地理对象 | 建议改成「活动 + 场地」模型：场地有坐标，活动有场次与起止时间，且不写进 POI 的营业时间字段 |

**产品侧必须做的降级**：这 4 条在 UI 上不能显示地图标记，也不能显示「距离/步行时间」。现有 `js/data.js` 里的 `DISCLAIMER.hours`（「营业信息待确认」）与 `DISCLAIMER.map`（「示意地图 · 不含真实坐标」）对它们仍然适用，不能因为接入了真实地图就一起升级为「真实信息」。

## 五、许可证与合规风险（本次最重要的未决项）

原要求是「注明来自维基百科 CC BY-SA 4.0」。**维基百科不可达，所以没有任何一段文字是 CC BY-SA。** 实际情况：

| 内容 | 来源 | 许可证 / 权利状态 | 能否直接用于产品 |
| --- | --- | --- | --- |
| 经纬度 | OpenStreetMap（经 Photon） | **ODbL 1.0**，© OpenStreetMap contributors | 可以，但必须署名（「© OpenStreetMap contributors，ODbL 1.0」）并遵守 ODbL 的衍生数据条款 |
| 玄武湖、老门东的 `extract` | 360百科正文 | **第三方版权内容**，非 CC BY-SA、非公有领域 | **不可以**直接用于产品发布。JSON 里已标 `extractType: "quote"` |
| 其余 5 条 `extract` | 360百科要点转述 | 同上，属「事实 + 转述」，风险低于逐字摘录但仍需法务确认 | 建议**改写成自有文案**后再上线 |
| 白鹭洲公园 `extract` | OSM 标签推导 | ODbL 1.0 | 可以 |

**结论**：`poi-enrichment.json` 目前适合做**内部核验与结构对接**，不适合直接把文字搬上生产界面。两条逐字摘录（`p_xuanwu`、`p_laomendong`）尤其需要替换。若产品坚持要 CC BY-SA 的维基文案，必须在**能访问维基百科的网络环境**重跑一次 enrichment，或改用自有文案团队撰写。

## 七、如何复核本文件里的每一个数

1. **复核坐标**：打开 `poi-enrichment.json` 里对应条目的 `coordinateUrl`（Photon 查询 URL），返回的 GeoJSON 应包含同一个 `osm_type`/`osm_id` 与同一对坐标。注意 Photon 返回的 `coordinates` 是 `[经度, 纬度]`（GeoJSON 顺序），与本文件表格的「纬度在前」相反，比对时别弄反。
2. **复核文字**：打开 `pageUrl`，比对 `extract`。`extractType` 说明它是对应页面的逐字摘录（`quote`）、要点转述（`paraphrase`）、OSM 推导（`derived-from-osm`）还是占位说明（`placeholder`）。
3. **复核营业时间**：只有 `hours` 非 `null` 的条目才有 `hoursSource` 与 `hoursPageDate`，且都指向明确写出该时间的页面。
