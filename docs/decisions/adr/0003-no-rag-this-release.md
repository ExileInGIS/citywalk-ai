# ADR 0003 · 本期不做 RAG，改用结构化数据与规则解释

- 状态：已采纳
- 日期：2026-10-26
- 决策者：PM（依据地点数据核验与竞品研究）

## 背景

RAG 的潜在价值是地点历史/街区背景与路线主题解释。但本期实测：

- 本机无法访问 zh/en.wikipedia.org、api.wikimedia.org、wikidata.org、archive.org、openstreetmap.org 与 Nominatim；
- 唯一可访问的中文百科文本（360 百科）是第三方版权内容，只能内部核验，不能进入产品；
- 可追溯的只有 OpenStreetMap 坐标（ODbL 1.0）。

## 选项

- A. 用 360 百科文本做 RAG：有内容，但有版权风险，且无法保证引用合规；
- B. 用模型记忆生成地点介绍：无法验证，违背“不编造”的要求；
- C. 本期不做 RAG，用结构化属性 + 确定性规则 + 模板化理由 + 来源字段：可验证、可测试；
- D. 等待可访问维基的环境再实现：阻塞交付，不可取。

## 决定

选择 C；本期不实现检索，不产生任何“检索结果”。

## 理由

1. 产品核心价值是约束满足、局部修改与可解释，不依赖知识库；
2. 没有合规语料时，RAG 会自然滑向编造；
3. 没有真实 LLM 密钥，无法做有意义的 RAG/无 RAG 对照评测。

## 后果

- 地点介绍保持简短、基于已有产品文案与可验证属性；
- `docs/RAG-DESIGN.md` 保留未来方案（数据源/许可、切分、检索、引用、评测集、对照实验）；
- 未来拿到维基/Wikimedia 访问与许可后，再按该设计实现并评测。

## 验证

`docs/RAG-DESIGN.md`、`docs/research/poi-sources.md`；Route `sources` 只包含真实 URL（OSM 版权页、项目仓库）。
