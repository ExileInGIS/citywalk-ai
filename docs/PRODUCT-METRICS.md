# CityWalk AI 指标体系与埋点方案

> 版本：v1.0 · 2026-10-26
> 原则：**没有真实用户数据就不报告转化率、留存或增长**。本文件定义「怎么量」，并提供本次可真实执行的离线评测口径；真实流量指标标注为「待上线」。

---

## 1. 指标设计原则

1. **可复算**：每个指标给出分子、分母、事件与时间窗，任何人用同一份事件/测试集能复现。
2. **不混口径**：Mock、Remote、离线评测三种来源分开报告，不合并成一个「成功率」。
3. **失败可见**：超时、非法输出、降级、用户放弃都计入失败或单列，不静默剔除。
4. **隐私最小化**：事件不含自由文本、预算、同行人、精确位置；只保留任务类型、耗时、结果码、模式、路线 id。
5. **先离线后线上**：本次交付离线评测与事件管线；线上指标需真实用户与时间，未执行前不写数字。

---

## 2. 事件模型

### 2.1 公共字段

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `event` | string | 事件名（见下表） |
| `ts` | ISO8601 | 客户端时间 |
| `sessionId` | string | 匿名会话 id（localStorage，随机 UUID，不含用户身份） |
| `routeId` | string? | 路线 id（不包含个人信息） |
| `mode` | `mock`/`remote` | 本次调用模式 |
| `task` | `plan`/`refine` | 任务类型 |
| `durationMs` | number? | 客户端耗时 |
| `errorCode` | string? | 标准化错误码 |
| `appVersion` | string | 前端版本 |
| `degraded` | boolean? | 是否降级 |

### 2.2 事件清单

| 事件 | 触发时机 | 关键属性 | 用途 |
| --- | --- | --- | --- |
| `plan_started` | 用户点击生成且通过前端校验 | `task`, `mode` | 成功率分母 |
| `clarify_shown` | 服务端返回澄清 | `missingCount`（数字，不含字段内容？字段名可） | 信息缺失率 |
| `clarify_answered` | 用户提交澄清答案 | `answeredCount`, `skippedCount` | 追问有效性 |
| `plan_succeeded` | 收到合法 Route 并渲染 | `placeCount`, `durationMs`, `degraded` | 成功率/耗时 |
| `plan_failed` | 请求失败或渲染失败 | `errorCode`, `durationMs` | 失败归因 |
| `refine_started` | 发送调整指令 | `mode` | 调整成功率分母 |
| `refine_succeeded` | 收到合法 RefineResult 且路线更新 | `changed`, `changesCount`, `durationMs` | 调整成功率 |
| `refine_failed` | 请求/校验失败 | `errorCode` | 失败归因 |
| `conflict_shown` | 结果含 conflict | `conflictType` | 冲突频率 |
| `conflict_option_clicked` | 用户选择冲突选项 | `conflictType`, `optionId` | 冲突解决方式 |
| `route_saved` | 收藏路线成功 | `source` | 保存率 |
| `route_exported` | 导出 Markdown/JSON 成功 | `format` | 导出率 |
| `route_copied` | 复制分享文本成功 | — | 分享意愿 |
| `agent_degraded` | 远程失败切 Mock | `reasonCode` | 降级率 |
| `map_failed` | 地图 Provider 初始化/加载失败 | `provider`, `reasonCode` | 地图稳定性 |
| `retry_clicked` | 用户点击重试 | `context` | 恢复行为 |

> 禁止字段：`text`、`conditions`、`budget`、`party`、`accessibility`、`lat/lng`、IP 明文。服务端日志同样不记录这些内容。

## 3. 核心指标定义

| # | 指标 | 定义 | 分子 | 分母 | 统计对象 | 事件/数据源 | 适用场景 | 可能的误判 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| M1 | 规划任务成功率 | 一次规划请求最终渲染出合法路线 | `plan_succeeded` | `plan_started` | 会话内每次生成 | 埋点 | 全量 | 用户中途放弃被计失败；Remote 与 Mock 需分开 |
| M2 | 用户约束满足率 | 适用硬约束中被满足的比例 | 满足硬约束数 | 适用硬约束数 | 每条路线 | 离线评测 + 服务端 | 全量 | 无数据的约束按 unknown 不计入分子/分母；需单列 unknown 率 |
| M3 | 必填信息识别准确率 | 系统判断「哪些必填项缺失」的正确率 | 正确判断的必填项 | 标注的必填项 | 每条输入 | 标注测试集 | 离线 | 标注主观；中文表达多样 |
| M4 | 路线结构有效率 | 通过 JSON Schema 与引用完整性校验的路线比例 | 通过校验路线数 | 生成路线数 | 每条路线 | 评测 | 全量 | Schema 通过 ≠ 业务正确 |
| M5 | 地点数据可验证率 | 有可追溯来源的地点比例 | 有来源地点数 | 全部地点数 | 地点库 | 数据审计 | 数据版本 | 来源质量不一；坐标与名称匹配需人工抽检 |
| M6 | 自然语言调整成功率 | 调整请求返回合法结果且路线确实变化/明确无需变化 | `refine_succeeded` | `refine_started` | 每次调整 | 埋点 + 评测 | 全量 | 用户指令本身不可执行；需区分「无效指令」 |
| M7 | 首次有效路线生成耗时 | 从 `plan_started` 到首个合法 Route 的耗时 | — | — | 每次生成 | 埋点/评测 | 分 Mock/Remote | 网络波动；Mock 与真实服务不可混比 |
| M8 | 错误恢复成功率 | 失败后通过重试/降级获得合法结果的比例 | 恢复成功次数 | 失败后重试次数 | 会话 | 埋点 | 全量 | 样本少；降级不应算「真实服务恢复」 |
| M9 | 用户主动重新规划比例 | 同会话重复发起 plan 的比例 | 重复 plan 次数 | 会话数 | 会话 | 埋点 | 全量 | 正常改需求被误判为负面 |
| M10 | 保存或复制路线比例 | 生成后保存/导出/复制的比例 | `route_saved`+`route_exported`+`route_copied` | `plan_succeeded` | 每次成功生成 | 埋点 | 全量 | 无真实流量前不报告 |

### 3.1 口径细节

- **M1**：一次 `plan_started` 后 60 秒内没有 `plan_succeeded`/`plan_failed`，按「无响应」单列，不并入成功。
- **M2**：硬约束包括 `durationMax`、`budgetMax`、`mustVisit`、`avoid`、`walkingMax`、`accessibility`（有数据时）。`unknown` 单独统计，不冒充满足。
- **M3**：测试集对每条输入标注应缺失项；系统返回 clarification 的字段集合与标注比对（集合相等才算对）。
- **M6**：`changed=false` 且 `reply` 明确说明「无需修改/无法识别」不算成功；`changed=true` 但未通过约束校验也不算成功。
- **M7**：P50/P90 分开；服务端耗时与端到端耗时分开。
- **M10**：同一路线重复保存只计一次。

## 4. 离线评测方案（本次真实执行）

### 4.1 测试集

- 位置：`qa/eval/cases.json`（固定 24 条，覆盖 PRD 第 13 节 20 类场景）；
- 每条：`id`、`category`、`input`（conditions/text）、`expected`（必去/预算/时长/失败类型）、`notes`；
- 固定数据版本与代码版本；运行时记录 `git rev-parse HEAD` 与数据 hash。

### 4.2 对比基线

| 基线 | 说明 | 本次是否运行 |
| --- | --- | --- |
| B0 随机/热门基线 | 按热度取前 N 个地点、固定顺序，不做约束校验 | 是（脚本实现） |
| B1 原始原型规则 | 从原 `js/agent.js` 迁移的贪心 + 扫掠，无新增约束/校验 | 是（保留函数） |
| B2 优化工作流 | 本次的检索+约束+排序+校验+解释 | 是 |
| B3 远程 LLM | 需真实密钥 | **否，标记未验证** |

### 4.3 指标

- 约束满足率（M2）；
- 结构有效率（M4）；
- 调整成功率（M6，固定 12 条调整指令）；
- 异常恢复率（M8，注入超时/非法 JSON）；
- 端到端耗时（M7，Mock 环境）；
- 地点可验证率（M5）。

### 4.4 失败分析

每条失败记录：`caseId`、基线、失败类型（schema/约束/排序/数据/异常）、原因分类、修复动作、回归结果。报告写入 `docs/EVALUATION-REPORT.md`，**只放实际运行输出**。

## 5. 数据采集与存储

| 层 | 方案 | 说明 |
| --- | --- | --- |
| 客户端 | `js/telemetry.js` 内存队列 + 批量 POST `/api/events` | 失败静默重试 1 次；不阻塞主流程；可关闭 |
| 服务端 | 结构化 JSON 日志 + 内存聚合（本次不落库） | 进程重启即清空；仅用于本地演示 |
| 离线评测 | `scripts/eval.js` 输出 JSON + Markdown | 可重跑，数字进文档 |
| 隐私 | 无 PII；不记录用户文本；不关联身份 | 见 PRD 第 11 节 |

> 本次没有真实用户与生产环境，因此**不产生**真实转化率、留存率、DAU 等指标；任何此类数字都不会出现在交付物中。

## 6. 指标与产品的对应关系

| 指标 | 若变差，说明什么 | 产品动作 |
| --- | --- | --- |
| M1 ↓ | 服务不稳定或校验过严 | 看错误码分布；降级策略；修复 Schema |
| M2 ↓ | 约束冲突处理不足 | 增选项、改排序、补数据 |
| M3 ↓ | 解析/追问不准 | 补同义词、上下文记忆、澄清 UI |
| M4 ↓ | 模型输出漂移 | Prompt/工具约束、修复重试、收紧 Schema |
| M6 ↓ | 调整能力不足 | 补指令类型、保留策略、差异解释 |
| M8 ↓ | 降级/重试无效 | 修超时、缓存、错误提示 |
| M10 ↓ | 结果不够可用/可信 | 理由、来源、导出体验 |

---

## 7. 报告规范

- 每次评测必须写：日期、代码 commit、数据版本、运行命令、环境（OS/Node）、样本量、指标表、失败样例、结论与限制；
- 不允许只写「效果良好」；
- Mock 与 Remote 分开；未运行写「未运行」；
- 对外作品集引用数字时必须附命令与报告链接。
