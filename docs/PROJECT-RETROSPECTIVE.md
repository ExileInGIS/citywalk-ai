# CityWalk AI 项目复盘与作品集说明

> 版本：v1.0 · 2026-10-26
> 说明：本文只写实际发生的工作与可复现的证据；未验证项明确标注。

---

## 1. 项目目标与起点

**目标**：把 GitHub 上的 `citywalk-ai` 高保真原型升级为具有真实业务逻辑、完整交互闭环、可接入真实 AI/地图服务、可测试、具备部署条件的 Web 产品。

**起点（审计结论，详见 `docs/CODE-AUDIT.md`）**：
- 三页前端交互完整，视觉语言成熟，可复用；
- AI 是浏览器本地规则模拟，无后端、无 `/api/agent/run`、无结构化校验；
- 地图是手绘 SVG 示意，无真实坐标；
- 测试脚本硬编码作者本机路径，无法运行；无 `package.json`；
- 无障碍与响应式有明显缺口（0 个 `aria` 属性、固定 1440 视口）。

## 3. 产品结果

### 3.1 可运行闭环

Mock 模式（无需密钥）可完成：

```
输入需求 → 缺失信息追问 → 生成路线 → 地图/时间线/摘要联动
→ 自然语言调整 → 前后差异与约束清单 → 保存/导出
```

### 3.2 关键产品能力

- **约束优先**：时间、预算、必去、避开、步行上限由确定性代码校验；冲突给选项，不静默放宽；
- **可解释**：每站有理由，整条路线有分项评分、约束状态、数据来源与不确定提示；
- **可局部修改**：8 类以上自然语言指令，保留未受影响的站点，重算受影响段；
- **诚实标注**：Mock/Remote、降级、估算、未验证营业信息、泛化地点在界面上一眼可见；
- **服务化**：统一 `/api/agent/run`，requestId/traceId、Schema 校验、超时、限流、降级；
- **可替换**：Agent 与地图均为 Provider 契约，Mock 是默认实现。

### 3.3 量化结果（以实际运行报告为准）

| 指标 | 结果 | 来源 |
| --- | --- | --- |
| 自动化测试 | 见 `docs/EVALUATION-REPORT.md` 与交付总结 | `pnpm test` |
| 固定评测集 | 24 条规划场景 + 12 条调整指令 | `qa/eval/` |
| 地点坐标可验证率 | 8/12（OSM，ODbL） | `server/data/poi-coords.json` |
| 文档 | 12 份必需文档 + ADR + 设计系统 | `docs/` |
| 真实 LLM / 地图 / 公网 | **未验证 / 未部署** | 见第 6 节 |

> 没有真实用户数据，因此不报告转化率、留存率或增长；评测只证明 Mock 行为与工程质量。

## 4. 关键技术决策（均可推翻）

| 决策 | 选择 | 理由 | 记录 |
| --- | --- | --- | --- |
| 前端框架 | 保留原生 HTML/CSS/JS | 保留已验证交互，降低重写风险 | ADR 0001 |
| 后端 | Node 内置 http，零运行时依赖 | 4 个接口足够，供应链面小，启动简单 | ADR 0002 |
| 规划代码 | 浏览器与 Node 共用 `shared/core.js` | 防止两套逻辑漂移，Mock 可离线 | ADR 0004 |
| RAG | 本期不做，结构化数据 + 规则解释 | 无可用的合规语料，避免编造 | ADR 0003、`RAG-DESIGN.md` |
| 存储 | localStorage，无账号 | MVP 无需账号，隐私边界清晰 | PRD 第 11 节 |
| 依赖 | 运行时零依赖；jsdom 仅开发测试 | 可复现、安装小 | package.json |
| 校验 | 自写轻量 Schema | 避免运行时依赖，覆盖固定契约 | `js/schema.js` |

## 5. 遇到的真实问题与处理

| 问题 | 影响 | 处理 | 证据 |
| --- | --- | --- | --- |
| 仓库未挂载、git 直连 GitHub 失败 | 无法 clone | 用 HTTPS 工具下载 tarball；`git hash-object` 对照 8 个文件哈希全部一致 | `CODE-AUDIT.md` 第 2 节 |
| 上游测试硬编码 `/tmp/node_modules/jsdom` 与 `/Coze/Drive/...` | 无法复现「68+31 项检查」 | 重写测试体系；不引用旧数字 | `CODE-AUDIT.md` 第 28 项 |
| 中文维基百科/Wikidata 不可达 | 无法获得 CC BY-SA 语料 | 不做 RAG；坐标改用 OSM（ODbL）；注明 360 百科只作内部核验 | `RAG-DESIGN.md`、`poi-sources.md` |
| 无真实 LLM/地图密钥 | 无法证明真实链路 | 完成 Mock + 适配器 + 接入文档；报告中标「未验证」 | `API-INTEGRATION.md` |
| 无公网部署条件 | 不能上线 | 交付本地可运行版本 + 部署步骤；不写「已上线」 | `DEPLOYMENT.md` |
| 浏览器/服务端逻辑容易漂移 | 结果不一致 | 抽 UMD 共享核心，两端同一实现 | ADR 0004 |

> 这些不是「包装成亮点」的困难，而是审计与合规边界；处理方式都以可复现证据为准。

## 6. 局限（诚实清单）

1. **真实 LLM 未联调**：Prompt、Provider、修复重试已实现，但没有密钥，输出质量未经真实模型验证；
2. **Coze 适配器未验证**：需按官方文档核对并实测；
3. **真实地图未自动化**：Leaflet 需要网络/CDN/CSP；瓦片加载未在自动化中覆盖；
4. **路线不是导航**：距离 = 直线距离 × 1.25 的估算，站间连线为示意；
5. **仅南京示例数据**：12 个地点，4 个泛化地点无坐标；
6. **无障碍只做到基线**：键盘、焦点、live region、对比度；未做屏幕阅读器实测；
7. **无真实用户研究**：用户画像与痛点均为假设，验证方法写在 PRD 第 3.4 节；
8. **图片版权未核实**：上线前需替换或取得授权；
9. **单文件版是构建产物**：由 `build.js` 生成，不提交仓库。

## 7. 下一步（按优先级）

1. **真实 LLM 联调**：用两到三个模型跑固定 24 条评测集，对比 Mock 与远程的约束满足率/结构有效率/耗时；把结果写进 `EVALUATION-REPORT.md`；
2. **真实地图联调**：Leaflet/高德各接一次，核对坐标、许可、CSP、归属标注；
3. **5 人可用性测试**：验证「自然语言修改」「约束清单」「差异面板」是否真的降低理解成本；
4. **数据核验**：用商业 POI 服务复核 8 个坐标与营业时间，补 4 个泛化地点的真实门店或改为「类型推荐」；
5. **上线**：HTTPS、域名、限流、日志、错误监控、隐私政策；
6. **RAG（有语料后）**：按 `RAG-DESIGN.md` 实现并做无 RAG 对照。

## 8. 作品集说明（可直接用于面试）

### 8.1 产品机会（一句话）

用户需要的不是「更多地点推荐」，而是**在时间、预算、体力、同行人等约束下，一条能走通、能解释、能改的路线**。

### 8.2 我的贡献

- 从 0 到 1 定义产品范围、MVP 优先级与验收标准（PRD/DoD/指标）；
- 把模糊的「AI 规划」拆成 Agent（理解/表达）+ Workflow（确定性计算/校验）的职责边界；
- 设计并落地统一 Agent API、Schema 契约、Mock/Remote 双模式与降级策略；
- 组织并行的竞品研究、设计系统、前后端实现、测试与文档；对结果做集成与验收；
- 坚持「不编造」：真实用户数据、真实 LLM、真实地图、上线状态都以未验证标注。

### 8.3 可经得起追问的量化证据

- 24 条固定评测场景、12 条调整指令、固定命令可重跑；
- 8/12 个地点有可追溯的 OSM 坐标，4 个明确标为无实体；
- 测试与评测报告包含环境、commit、命令、失败样例；
- 12 份文档与代码字段/命令对应，`scripts/check.js` 做一致性自检。

### 8.4 如果重做一次

- 更早冻结 Schema 与核心 API，减少并行实现的返工；
- 先做「澄清 + 约束冲突」这两条最影响信任的路径，再做视觉扩展；
- 把真实服务联调作为第一优先级的外部依赖，提前准备测试账号；
- 在 PRD 阶段就写清楚「数据可验证率」的验收线，避免后期补来源。
