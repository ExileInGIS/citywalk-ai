# CityWalk AI · 智能城市漫步规划助手

基于 AI Agent 的个性化城市漫步路线规划工具 —— 高保真、可交互的桌面端 Web 产品原型。

**核心价值**：把「模糊的出行想法」快速转成「满足兴趣偏好、时间预算和步行约束的可执行 CityWalk 路线」，减少地点搜索、信息筛选和路线规划的时间成本。

这不是一个聊天机器人页面，而是把 **AI 对话 · 需求配置 · 地图可视化 · 路线卡片 · 动态调整** 融合在一起的完整产品。

## 一、如何打开

| 版本 | 文件 | 用途 |
| --- | --- | --- |
| **单文件版（推荐直接打开）** | `CityWalk-AI.html` | CSS / JS / 12 张图片全部内联，双击即可运行，无需服务器、不依赖任何网络资源 |
| 多文件版（便于二次开发） | `index.html` + `css/` + `js/` | 结构清晰、按模块拆分，需与同级目录一起打开 |

```bash
# 需要重新打包单文件版时（改了 css/js 之后）
node build.js
```

> 单文件版是为了规避「浏览器直接打开本地 HTML 时相对路径资源加载失败」的问题，功能与多文件版完全一致。

## 三、信息架构

### 顶部导航栏
品牌标识 · 首页 / 发现路线 / 我的收藏 · 城市选择器（默认南京）· 帮助 · 用户头像

### 首页：AI 路线规划工作台（左右 42% / 58%）
- **左栏（输入与交互）**
  - 标题与副标题、自然语言输入框（200 字计数、示例一键填充）
  - 快捷需求标签：咖啡与甜品 / 历史文化 / 城市摄影 / 独立书店 / 公园与绿地 / 本地特色
  - 可展开的高级筛选：出发位置、出行日期与开始时间、可用时长（2/3/4/6 小时）、预算范围、步行强度（轻松/适中/深度探索）、兴趣多选、出行方式、必须到达时间
  - 主 CTA「生成我的 CityWalk 路线」→ 4 步 AI 规划进度
  - 生成后：**本次规划条件卡**（可查看、可修改）+ **AI 对话面板**（6 类调整指令 + 快捷指令 chip）
- **右栏（预览与结果）**
  - 未生成：精选路线预览 + 地点发现网格（6 张）
  - 生成中：理解偏好 → 筛选地点 → 组织顺序 → 检查约束
  - 生成后：路线摘要卡 → 示意地图 → 纵向时间线地点卡片

### 发现路线
城市 / 主题 / 时长三组筛选 + 路线卡片网格；每张卡片提供「查看路线」与「使用此路线重新规划」（把主题与地点偏好带回首页规划流程）。

### 我的收藏
收藏路线列表 + 收藏地点列表，支持查看详情、再次规划、移除收藏；未收藏时展示空状态与引导。

## 四、主流程（可在原型中完整走通）

```
填写出行需求（自然语言 / 表单，两者互相配合）
   ↓
点击生成 → 4 步规划进度
   ↓
查看示意地图 + 路线摘要 + 时间线地点卡片
   ↓
对话式修改（缩短步行 / 增删某类地点 / 改时长 / 改预算 / 调节奏）
   ↓  ← 展示「修改前后对比」，约束冲突时给选项而不是直接忽略
更新路线（摘要、顺序、标签、地图标记同步刷新）
   ↓
收藏路线 / 分享路线 / 重新规划
```

## 五、AI 层的「模拟 / 真实」边界（重要）

`js/agent.js` 顶部有明确声明，当前 **100% 为本地规则模拟**，仅用于演示产品交互与状态流转：

| 能力 | 当前实现 | 未来接入点 |
| --- | --- | --- |
| 需求解析 | `parseIntent()` 关键词规则 | 真实 LLM 语义理解 |
| 路线生成 | `planRoute()` 本地打分 + 就近插入贪心 | 真实 POI 检索 + 路径规划 API |
| 对话修改 | `applyInstruction()` 规则匹配 + 状态更新 | 真实 Agent function calling |
| 冲突检测 | `buildRoute()` 内本地规则 | 真实可达性/时间窗计算 |

**唯一开关**：

```js
const CONFIG = {
  mode: 'mock',   // 改成 'remote' 并填入 endpoint，即切换到真实服务
  endpoint: '',   // 例如 '/api/agent/plan'（当前为空）
  provider: '',
  latency: [420, 780]
};
```

所有 AI 能力都经由单一入口 `CW.agent.run(task, payload)` 调用，切换到真实服务时业务代码无需改动。当前 `mode = 'mock'`，界面上标注「演示模式 · 本地模拟规划」，**不会声称已接入任何大模型或 Coze 后端**。

### 规划算法（模拟，但内部自洽）
1. **打分**：直接命中地点兴趣标签 +5，仅类别沾边 +1；节奏契合度微调；低预算时弱化高消费地点。
2. **候选**：取分数靠前的一批（有时长与节奏换算出的目标地点数上限）；有匹配地点时不混入完全无关的地点。
3. **填充**：以「就近插入成本」（停留时长 + 到已选地点的最近步行时间）贪心纳入，在时间预算内优先保住高偏好地点。
4. **排序**：按地理走向（西北 → 东南）扫掠排序，形成少走回头路的步行序列。
5. **估算**：示意坐标 → 距离（1 图幅单位 ≈ 8 米）→ 步行时间（75 米/分钟），并汇总停留时间、消费区间。
6. **冲突**：超时 10% 以上判为硬冲突并给出可操作选项；10% 以内只做提示；预算上限超限单独提示。

## 六、需求缺失与异常处理（差异化功能）

| 场景 | 实现 |
| --- | --- |
| 只输入「帮我规划一条 CityWalk 路线」 | 主动追问最关键信息：「你想在哪座城市漫步？预计有多少时间？」并给出快捷选项，不凭空补全 |
| 未填写预算 | 允许继续规划，预算显示为「**未指定**」，不替用户认定预算 |
| 时间约束与行程冲突 | 给出明确冲突说明 + 可操作建议（减少一个地点 / 调整为轻松节奏），由用户选优先级 |
| 营业时间或交通信息缺失 | 显示「**信息待确认**」「时间为估算值」，不虚构实时数据 |
| 未选择任何兴趣标签 | 按自然语言继续处理；关键信息仍不足时通过对话补充，不强制填满表单 |
| 时间还有富余 | 提示实际安排时长与富余量，建议放宽兴趣或切换深度探索 |
| 手动调整顺序 | 明确提示「本原型不具备真实路径计算能力，**距离与时间未重新计算**」，地图编号同步更新 |

## 七、数据与合规标注

- 全部地点、路线、时长、距离、消费区间均为 **示例数据 / 估算值**，界面上通过统一的 `DISCLAIMER` 文案出口标注。
- 所有地点的营业时间均为 `null`，界面一律显示「信息待确认」。
- 地图为 **SVG 示意地图**（自绘街区、水系、城墙、绿地），**不含真实坐标**，不伪造任何地图 API 的调用结果；标记坐标仅用于示意与排序计算。
- 收藏数据仅保存在前端内存中（本次会话有效），不涉及账号系统与数据库。
