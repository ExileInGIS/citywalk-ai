# 原型设计规范 · CityWalk AI

> 本文件把 skill 的通用原型规范替换为本产品的真实技术路线与视觉规范。通用骨架仍适用，但**技术路线、token 与限制以本文件为准**。

## 一、技术路线

**本产品采用「多文件原型」而非「单需求单文件」：**

```text
index.html          ← 多文件版入口（顶栏 + 主内容容器 + 脚本按序引入）
css/style.css       ← 设计系统实现：:root token + 全部组件与页面样式
js/config.js        ← 唯一接入开关（AI 模式 / 地图 provider / 收藏存储）
js/data.js          ← 数据层（城市/兴趣/节奏/交通/地点/精选路线/统一免责文案）
js/ui.js            ← 工具层（DOM 助手、内联 SVG 图标、Toast、模态框、格式化）
js/agent.js         ← AI 层（当前本地规则模拟）
js/map.js           ← 地图层（SVG 示意地图 + 适配器注册表）
js/app.js           ← 应用层（全局状态、路由、顶栏渲染）
js/pages/*.js       ← 页面层（home / discover / favorites）
build.js            ← 可选：node build.js 产出单文件 CityWalk-AI.html
```

**核心原则：**

- 无框架、无打包器、无 npm 运行时依赖，`index.html` 直接可开（`<script>` 按序加载，`js/config.js` 必须最先）；
- 组件全部手写 CSS，不引 UI 库；
- 图片走本地 `assets/img/`，不依赖 CDN；
- 单文件版只用于离线分发，不是开发主形态——**改完 `css/`、`js/` 要重新 `node build.js`**，否则单文件版与多文件版不一致。

**为什么不用「一个需求一个单文件 HTML」：** 本产品已经是一个完整应用（三页路由、全局状态、地图适配器、AI 对话）。再给每个需求生成一个独立的单文件原型，会立刻出现第二套视觉语言和第二套交互逻辑，评审时就无法判断「线上到底是哪一版」。仅在一次大改版需要并排比稿时，才按 `00-产品专属规则.md` 第 4 节的约定放独立原型。

## 三、文件结构模板（新增独立原型时）

```html
<!DOCTYPE html>
<html lang="zh-CN">
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=1440">
  <title>{原型标题} · CityWalk AI</title>
  <style>
    /* 1. 从 docs/design/tokens.json 抄 :root，禁止保留模板的蓝色企业色 */
    /* 2. 通用组件（按钮 / 输入 / 卡片 / 弹窗 / Toast）与 css/style.css 同名同值 */
    /* 3. 页面特有样式 */
  </style>
</head>
<body>
  <!-- 顶栏结构照抄 index.html 的 .topbar，保持品牌与导航一致 -->
  <script>/* 页面交互 */</script>
</body>
</html>
```

## 四、组件实现说明

本产品**已有**的组件（直接复用，不要重画）：按钮、胶囊筛选、标签、输入框/下拉/分段控件、卡片、路线卡、地点卡、时间线、地图卡、摘要卡、对话气泡、模态框、Toast、加载四步、空状态、提示条。清单与状态见 `../docs/DESIGN-SYSTEM.md` 第 4、5 节。

`组件模板/` 的四个模板来自 skill 通用层，**样式是蓝色企业后台风，只借结构不借配色**：

| 模板 | 借用什么 | 用在本产品的哪里 |
| --- | --- | --- |
| `标准列表页.html` | 工具栏 + 表格/网格 + 分页的结构 | 发现路线（网格）、我的收藏（列表） |
| `侧滑详情.html` | 右侧滑出的详情结构 | 地点详情、路线详情（本产品实际用居中弹窗，侧滑可作为移动端方案） |
| `弹窗表单.html` | 表单字段 + 底部操作 | 分享路线、个人中心 |
| `多选弹窗.html` | 多选 + 已选计数 | 兴趣偏好多选（本产品实际用胶囊矩阵，弹窗版适合兴趣扩充到 12+ 项时） |

## 五、限制

1. **桌面优先**：现有实现固定 `viewport width=1440`，仅一个 `@media (max-width:1280px)` 断点。未做移动端适配前，不得声称「支持手机」。
2. **不做假数据**：营业时间一律 `hours: null` → 界面显示「信息待确认」；距离与时间为估算值；地图不含真实坐标。任何新增界面文案都必须保留这一层诚实标注（统一出口 `D.DISCLAIMER`）。
3. **不冒充 AI**：`js/agent.js` 当前为本地规则模拟，界面必须显示「演示模式 · 本地规则模拟」；接入真实服务后才允许改为「已连接智能体服务」（由 `CW.agent.status().connected` 决定）。
4. **不引新依赖**：新增视觉能力（图标、图表、动画）必须手写 SVG/CSS。确需引入第三方库，先升级 `00-产品专属规则.md` 第 2 节并经产品确认。
5. **不改既有视觉语言**：墨绿 + 米白 + 暖橙的杂志气质是本产品的识别核心，任何新页面必须在这套 token 内完成，不另起配色。
