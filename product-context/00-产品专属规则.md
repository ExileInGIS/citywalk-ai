# 产品专属规则 · CityWalk AI

> 本文件填写产品设计系统「二、产品专属规则」。通用规则见 skill 的 `SKILL.md` 第一章，本文件只写本产品自己的事实与约定。
> 版本：v1.0 ｜ 日期：2026-10-26 ｜ 维护人：产品设计

## 1. 产品背景

- **平台名称**：CityWalk AI（界面品牌标识为 `CityWalk` + 橙色 `AI`，见 `index.html` 顶栏 `.brand-text`）
- **产品定位**：中文城市漫步（CityWalk）AI 路线规划 Web 产品。把「模糊的出行想法」转成「满足兴趣偏好、时间预算与步行约束的可执行路线」。
- **产品形态**：桌面端优先的高保真交互原型，原生 HTML/CSS/JS 单页应用 + SVG 示意地图，三页路由（首页 / 发现路线 / 我的收藏）。
- **产品线**：
  - **路线规划（首页工作台）**：自然语言 + 表单双通道录入需求 → 生成路线 → 地图与时间线联动查看 → 对话式调整。核心职责是把需求变成一条可执行的路线。
  - **路线发现（发现路线）**：按城市 / 主题 / 时长筛选精选路线，可查看详情、收藏、作为起点重新规划。核心职责是降低「不知道去哪」的启动成本。
  - **个人收藏（我的收藏）**：收藏路线与地点，支持再次规划、查看、移除。核心职责是承接复访需求（当前为会话内存态，无账号体系）。

## 2. 技术栈约束

- **前端组件库**：**无**。本产品不使用 Element Plus / Ant Design 等组件库，所有组件由原生 CSS 手写（`css/style.css`）。新增组件必须复用既有 CSS 变量，不得引入同类 UI 框架。
- **框架与构建**：无框架、无打包器、无 npm 运行时依赖。`index.html` 直接按序引入 `js/*.js`；`build.js` 仅做「内联 CSS/JS + 图片转 base64」的单文件打包，不是构建系统。
- **原型技术路线**：多文件原型（`index.html` + `css/` + `js/`）+ `node build.js` 产出单文件版。详见 `01-原型设计规范.md`。
- **设计 token 事实源**：`docs/design/tokens.json`（机器可读）+ `docs/DESIGN-SYSTEM.md`（人读规范）+ `css/style.css` 的 `:root`（运行时实现）。三者必须一致，改色先改 `:root` 与 tokens.json，再更新规范。
- **数据与 AI 边界**：AI 规划层 `js/agent.js` 当前为本地规则模拟（`mode: 'mock'`），地图为自绘 SVG 示意地图（`provider: 'svg'`）。界面必须如实标注，不得暗示已接入大模型或真实导航。
- **自检命令**：`node tests/smoke.js`（主流程 68 项）、`node tests/checks.js`（异常与结构 31 项）。
- **工作语言**：文档、界面文案为中文；代码标识符与提交信息为英文；界面文案在需求文档中一律用「」包裹。

## 3. 业务术语

术语以 `05-业务术语表.md` 为准，界面文案与需求文档必须与该表一致。新增术语先加表、再使用，不修改既有条目。

易混淆的三组，写文档时必须区分：

| 不要混用 | 正确定义 |
| --- | --- |
| 路线 / 行程 / 计划 | 统一用**路线**（Route）。「行程」只在「行程时间线」这一组件名中出现 |
| 地点 / 景点 / POI | 统一用**地点**（Place）。「景点」暗示门票景区，本产品是城市漫步，不适用 |
| 估算值 / 实际值 | 本产品全部时长、距离、费用均为**估算值**，不得写成「实时」「实际」 |

## 4. 目录结构与版本说明

本仓库是「一个产品一个原型」，不按 `v{版本}/` 分目录。新增需求的两条路径：

```text
Citywalk_Agent/
├── index.html                     # 多文件版入口（顶栏 + 主内容容器 + 脚本按序引入）
├── css/style.css                  # 设计系统实现：:root token + 全部组件与页面样式
├── js/
│   ├── config.js                  # 唯一接入开关（agent.mode / map.provider / storage）
│   ├── data.js                    # 数据层：城市 / 兴趣 / 节奏 / 交通 / 12 地点 / 6 条精选路线 / DISCLAIMER
│   ├── ui.js                      # 工具层：DOM 助手、40+ 内联 SVG 图标、Toast、模态框、格式化
│   ├── agent.js                   # AI 层（模拟）：需求解析 / 路线规划 / 对话修改 / 冲突检测
│   ├── map.js                     # 地图层：SVG 示意地图 + 适配器注册表
│   ├── app.js                     # 应用层：全局状态、路由、顶栏渲染
│   └── pages/                     # 页面层：home.js / discover.js / favorites.js
├── assets/img/                    # 12 张地点图片（560×374 JPEG q72）
├── tests/                         # smoke.js / checks.js
├── build.js                       # 单文件打包脚本
├── docs/
│   ├── DESIGN-SYSTEM.md           # 设计系统规范（视觉/组件/可访问性/差距清单）
│   ├── design/tokens.json         # 机器可读设计 token
│   ├── API-INTEGRATION.md         # 智能体与地图接入指南
│   └── requirements/<需求名>/      # 【本轮约定】独立原型需求的三件套
│       ├── <需求名>.html
│       ├── 需求说明文档.md
│       └── CHANGELOG.md
└── product-context/               # 本设计知识库
```

**新增需求放哪里（本轮约定）**：

1. **默认走「改现有页面」**：本产品视觉语言已成型（墨绿 + 米白 + 暖橙），绝大多数需求应当直接扩展现有页面，不新建独立 HTML 原型——独立原型会立刻产生第二套视觉语言。
2. **确需独立原型时**（例如一次大改版的比稿、或需要并排对比两版方案），放 `docs/requirements/<需求名>/`，从 `组件模板/` 起步，**必须先把模板的 `:root` 蓝色企业色替换为 `docs/design/tokens.json` 的 CityWalk token**，否则视觉会与该产品脱节（模板自带 `--color-primary: #4A90E2` 一类的蓝色，与本产品 `--forest: #1F3D2B` 无关）。
3. **需求说明文档**新增页面时，必须补「权限说明」与「操作日志」两节。本产品当前无账号体系（游客态、数据仅存会话内存），因此这两节的写法是明确的**现状声明**，而不是省略：

```markdown
### N-1、权限说明
本页无需登录即可访问（当前为游客态，无账号体系）；页内所有操作均为本人可见的本地操作，不涉及跨用户数据。

### N、操作日志
当前原型无后端，不记录操作日志。接入账号体系时需记录：生成路线、调整路线、收藏 / 取消收藏、分享、移除收藏。
```

## 5. 文档分工（避免两种文档互相污染）

| 文档 | 读者 | 是否写实现细节（CSS 类名 / 函数名 / 行号） |
| --- | --- | --- |
| `docs/DESIGN-SYSTEM.md` | 设计 + 前端 | **写**，必须引用真实类名、变量名与行号 |
| `docs/design/tokens.json` | 前端 + 设计工具 | 只写 token，不写页面逻辑 |
| `需求说明文档.md` | 产品 + 测试 + 评审 | **不写**，只描述产品行为（skill 第一章第 2 节） |
| `product-context/01~05` | 设计 | 写规范与原则，案例可引用页面路径 |

`docs/DESIGN-SYSTEM.md` 是唯一允许、也要求出现 CSS 类名的产品文档。这条例外的原因：它服务的是「把现有视觉语言落成可复用 token」，不引用真实类名就落不了地。需求文档仍然遵守「不写实现细节」。
