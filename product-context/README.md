# CityWalk AI · 产品设计知识库

> 本目录是 CityWalk AI 的设计资产与规则沉淀，供产品、设计、前端在新建或修改需求时复用。通用骨架来自 `product-design-system` skill，本目录内是本产品填过真实内容的版本。

## 目录结构

| 文件/目录 | 用途 | 更新频率 |
| --- | --- | --- |
| `00-产品专属规则.md` | 【本产品专属】平台名称、产品线、技术栈约束、术语纪律、目录结构与文档分工 | 技术决策变更时 |
| `01-原型设计规范.md` | 本产品的原型技术路线与视觉规范（token 对照、文件结构、限制） | 技术决策变更时 |
| `02-设计原则库.md` | 从实际案例提炼的可复用设计原则（DP-xxx） | 每次需求复盘后 |
| `03-交互模式库.md` | 从实际需求提炼的交互流程模式（IP-xxx） | 每次需求复盘后 |
| `04-文案规范.md` | 界面文案与提示语规范，含本产品 AI 状态与可信度文案 | 按需 |
| `05-业务术语表.md` | 产品领域专业词汇与概念定义 | 按需 |
| `组件模板/` | 四个 HTML 原型模板（列表页 / 侧滑详情 / 弹窗表单 / 多选弹窗） | 按需 |
| `需求复盘/` | 复盘文档，`模板.md` 为填写格式 | 每个需求完成后 |
| `../docs/DESIGN-SYSTEM.md` | 设计系统规范：色彩、字体、组件状态、路线组件、AI 状态、可访问性、差距清单 | 改动界面时 |
| `../docs/design/tokens.json` | 机器可读设计 token（color / typography / spacing / radius / shadow / breakpoint） | 与上面的规范同步 |

## 快速入口

- **要动界面** → 先读 `../docs/DESIGN-SYSTEM.md`，再改 `css/style.css` 的 `:root` 与 `tokens.json`，三者保持一致。
- **要新建独立原型** → 参考 `01-原型设计规范.md` + `组件模板/`，**先把模板的蓝色企业色换成 CityWalk token**（`00-产品专属规则.md` 第 4 节第 2 条）。
- **要写需求说明** → 用 `../docs/requirements/<需求名>/需求说明文档.md`，写作风格按 skill 第一章第 2 节；**不写 CSS 类名与函数名**。
- **要复盘** → 用 `需求复盘/模板.md`，产出放 `需求复盘/<需求名称>-复盘.md`。

## 知识治理规则

1. **准入条件**：每条知识条目必须引用至少 1 个实际案例（本产品的页面路径、组件名或截图），并说明它提升下一次生成质量的方式。
2. **更新方式**：半自动——先提出候选条目，人工确认后写入；不直接把他人的设想写成正式规范。
3. **冲突处理**：产品专属规则（`00`）> 通用规则（skill 第一章）> 默认值。
4. **生命周期**：条目可标记为「已废弃」并注明替代条目，不删除历史记录。

## 与其他文档的边界

- 本目录写「怎么设计」；`../docs/DESIGN-SYSTEM.md` 写「现在长什么样、用什么 token、差在哪」。
- `../README.md` 面向使用者与开发者，写「这是什么、怎么跑」。三者不互相抄写。
