# 文案规范 · CityWalk AI

> 通用文案规则（格式、按钮命名、错误信息、空状态、确认弹窗）沿用 skill 第一章；本文件补充本产品的**真实文案清单**与**禁区**。
> 所有界面文案在需求文档中一律用「」包裹。

## 一、通用格式规则

- 界面文案（按钮名、标题、提示语）统一用「」书名号包裹（在需求文档中引用时）；
- 用 `>` 引用块展示 UI 上实际显示的文案原文；
- 文案中不出现技术术语（HTTP 状态码、接口名、`endpoint`、`mock`、`null` 等）；
- 用「请…」引导用户操作，不用「请您…」；
- 不出现 error、exception、null 等技术词汇。

## 二、按钮命名规范

| 操作类型 | 标准文案 | 本产品实际用词 |
| --- | --- | --- |
| 主操作（生成） | 「生成我的 CityWalk 路线」 | 已用（`home.js` 第 77 行）；已生成后变为「按当前条件重新生成」，生成中变为「正在为你规划…」并禁用 |
| 新建 | 「新建」 | 本产品不适用（无业务对象创建） |
| 编辑 | 「编辑」 | 本产品用「修改条件」「编辑条件」 |
| 删除 | 「删除」 | 本产品用「移除」「移除收藏」（不删数据，只移出列表） |
| 保存 | 「保存」 | 本产品无保存动作（状态即时生效） |
| 取消 | 「取消」「关闭」 | 弹窗底部「取消」（确认移除）与「关闭」（只读弹窗）两种 |
| 确认 | 「确认」 | 危险操作弹窗用「确认移除」 |
| 详情 | 「查看详情」 | 已用（地点卡、收藏列表） |
| 添加 | 「添加」「+ 添加」 | 本产品用对话指令（「加一家咖啡馆」），无独立添加按钮 |
| 重试 | 「重试」 | 本产品用「重新规划」；**错误气泡里当前没有重试按钮**（见 DESIGN-SYSTEM 差距 P1-6） |
| 收藏 | 「收藏路线」「收藏这个地点」「已收藏」「取消收藏」 | 已用，按对象区分 |
| 快捷体验 | 「一键体验」「使用此路线重新规划」「再次规划」 | 三个词分工：纯浏览用「一键体验」，从发现页带走条件用「使用此路线重新规划」，从收藏恢复用「再次规划」 |

## 三、AI 状态文案（本产品核心，必须一字不差对齐实现）

| 状态 | 触发条件 | 界面位置与文案 |
| --- | --- | --- |
| 演示模式（默认） | `CW.agent.status().connected === false` | AI 面板副标题：`演示模式 · 本地规则模拟`；生成按钮下方：`演示模式 · 本地模拟规划，未接入真实地图与导航服务` |
| 已连接 | `agent.mode === 'remote'` 且配置了 endpoint / request | AI 面板副标题：`已连接智能体服务` |
| 生成中 | `state.view === 'loading'` | 主按钮：`正在为你规划…`（禁用）；右栏标题：`正在为你规划路线`；副文案：`预计几秒内完成，你可以继续修改左侧的条件` |
| 降级 | 远程失败且 `fallback === 'mock'` | 对话气泡标题：`已切换为本地模拟`，正文：`智能体服务暂时不可用（{原因}），本次结果由本地规则生成，仅供参考。` |
| 规划失败 | `A.run('plan')` 抛错 | 对话气泡标题：`规划服务暂时不可用`，正文：`{原因}。请稍后重试，或检查 config.js 中的智能体服务配置。`（**`config.js` 属于技术词汇，面向终端用户时应改为「服务配置」**，见差距 P2-6） |
| 调整失败 | `A.run('refine')` 抛错 | 对话气泡标题：`调整失败`，正文：`{原因}。请稍后重试，或在高级筛选里手动修改条件。` |

**规则**：这三种状态（演示 / 已连接 / 已切换为本地模拟）必须由 `CW.agent.status()` 与返回值的 `degraded` 字段驱动，**不允许写死在模板字符串里**（见 DP-005）。

## 四、可信度与免责文案

统一出口 `D.DISCLAIMER`（`js/data.js` 第 278–283 行），不要各处手写：

| 键 | 文案 |
| --- | --- |
| `sample` | `示例数据 · 非真实导航结果` |
| `estimate` | `时长、距离与费用均为估算值` |
| `hours` | `营业信息待确认` |
| `map` | `示意地图 · 不含真实坐标` |

**用词规则：**

1. 时长、距离、费用出现时必须带「约」「估算」或「（估算）」之一，例如「全程约 4 小时 20 分」「步行约 3.1 km（估算）」；
2. 营业时间一律显示「信息待确认」，**不允许**出现具体时刻；
3. 地图相关文案必须含「示意」二字，不得写「地图导航」「实时路况」；
4. 免责说明必须出现在结果区的可见位置（不是折叠的详情里），当前实现是摘要卡下方的一行 `.note-box`。

| 收藏地点 | `已收藏地点，可在「我的收藏」查看` / `已取消收藏地点` |
| 复制成功 / 失败 | `已复制到剪贴板` / `复制失败，请手动选中复制` |

| 清空对话 | `对话已清空` |
| 展开筛选 | `已展开高级筛选，修改后点「按当前条件重新生成」` |
| 载入精选路线 | `已载入精选路线，可直接调整` |
| 筛选重置 | `筛选已重置` |
| 移除收藏 | `已移除收藏` / `已移除收藏地点` |

## 六、空状态文案

| 场景 | 主文案 | 副文案 |
| --- | --- | --- |
| 发现路线筛选无结果 | `没有符合条件的路线` | `换一个主题或时长试试。目前示例数据只覆盖南京老城区域，其他城市还在筹备中。` |
| 无收藏路线 | `还没有收藏路线` | `生成一条路线或从「发现路线」里挑一条，点「收藏路线」就会出现在这里。` |
| 无收藏地点 | `还没有收藏地点` | `在路线卡片或地点详情里点一下爱心，就会收藏到这里。` |
| 列表无数据（通用） | `暂无数据` | — |
| 搜索无结果（通用） | `未找到相关内容` | `请尝试其他关键词` |

空状态必须给出口按钮，不允许只有文案（见 IP-006）。

## 七、错误与冲突文案

| 场景 | 文案结构 | 本产品示例 |
| --- | --- | --- |
| 约束冲突 | 标题 + 量级 + 可执行选项 | `时间预算不足` / `按当前安排，全程约需 4 小时 40 分，超出你给的 3 小时。` + 「减少一个地点」「把节奏调整为轻松」 |
| 预算超限 | 「预算可能超出」+ 区间 | `按示例消费区间估算，全程约 ¥65–¥210，上限高于你设定的 ¥150。` |
| 必须填未填 | 追问 + 为什么需要 + 快捷选项 | `你想在哪座城市漫步？预计有多少时间？` / `有了城市和时长，我才能判断能安排几个地点、是否需要控制步行距离。` |
| 不可执行 | 说明原因 + 解决方向 | `地点已经很少了，建议放宽时间或改成轻松节奏。` |
| 关联限制 | 当前状态 + 可选动作 | `有 N 条收藏来自已重置的会话数据，无法还原，已从列表中隐藏。` |

**原则**：冲突文案必须同时给出「超了多少」与「可以怎么办」；只描述问题不给出口，等于把问题退回给用户。

## 八、写作禁区

1. **禁「实时 / 精准 / 保证 / 最佳 / 官方」**：产品没有实时数据源，这些词会构成事实性夸大。
2. **禁「已接入大模型 / AI 智能推荐（暗示真实模型）」**：当前为本地规则模拟，只能说「本地规则模拟」或「模拟规划结果」。
3. **禁把 `config.js`、`endpoint`、`mock`、`JSON` 等实现词汇写进面向用户的界面文案**（当前错误气泡里出现了 `config.js`，属于待修）。
4. **禁「游客用户，请登录解锁」类未实现的引导**：当前没有账号体系，收藏就是会话内存态，必须如实说「仅当前会话有效」。
5. **不用「可能大概也许」的双重模糊**：不确定就明确写「信息待确认」，不要用两三个模糊词叠加。
