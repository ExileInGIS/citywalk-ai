# 业务术语表 · CityWalk AI

> 产品核心业务术语定义，确保需求文档、界面文案与代码命名口径一致。
> 表中术语均来自现有实现（`js/data.js`、`js/agent.js`、`js/pages/*.js`）；新增术语按表格格式追加，不修改已有条目。

## 字段说明

| 字段 | 说明 |
| --- | --- |
| **术语** | 产品中使用的标准词汇 |
| **定义** | 简洁明确的含义说明（1-2 句话） |
| **所属模块** | 该术语归属的功能模块或业务域 |
| **相关术语** | 与之关联的其他术语 |

## 术语表

| 术语 | 定义 | 所属模块 | 相关术语 |
| --- | --- | --- | --- |
| CityWalk（城市漫步） | 以步行为主、围绕城市街区与生活场景的短途漫游方式，通常 2–6 小时、不追求景点打卡。本产品的品类名，不与「旅游线路」「徒步」混用。 | 全局 | 路线、路线节点 |
| 路线（Route） | 由若干地点按顺序组成、带时长与距离估算的一次漫步安排。界面上统一叫「路线」，不叫「行程」「计划」。 | 路线规划 | 路线节点、行程时间线、规划条件 |
| 规划条件（Conditions） | 生成路线所依据的一组输入：城市、可用时长、兴趣偏好、预算上限、步行强度、出行方式、出发位置、必须结束时间。对应代码 `conditions`。 | 路线规划 | 需求解析、规划条件卡 |
| 精选路线（Curated Route） | 由人工策划、非 AI 生成、地点顺序预设的路线，出现在「发现路线」与首页未生成时的预览区。携带 `source: 'curated'`，与 AI 生成的 `source: 'ai'` 区分。 | 发现路线 | 路线、一键体验 |
| 地点（Place） | 路线中的一个可停留点位，含类别、区域、推荐理由、建议停留、消费区间、营业时间状态。界面上叫「地点」，不叫「景点」「POI」。 | 全局 | 路线节点、地点详情 |
| 路线节点 / 站点 | 地点在一条具体路线中的一次出现，带顺序号（1、2、3…）、该次的停留时长与到上一站的步行耗时。同一地点可出现在不同路线中。 | 路线规划 | 路线、行程时间线 |
| 行程时间线（Timeline） | 结果页纵向排列路线节点的组件，显示顺序号、地点信息、推荐理由与上下站步行关系，支持拖动与上移/下移调整。 | 路线规划 | 路线节点、地图联动 |
| 停留时长（stay） | 在某个地点建议停留的分钟数，按步行强度系数折算，属于**估算值**。 | 路线规划 | 步行耗时、估算值 |
| 步行耗时（walkFromPrev） | 从上一站步行到本站的分钟数，由示意坐标距离换算，属于**估算值**。手动调整顺序后不重算（置为 `null` 并提示）。 | 路线规划 | 停留时长、顺序已手动调整 |
| 步行强度 / 节奏（Pace） | 三档预设：`轻松`（每小时约 1 个地点、多留休息）、`适中`（均衡）、`深度探索`（更多地点、步行更多）。影响停留时长系数与地点数量上限。 | 路线规划 | 规划条件、停留时长 |
| 兴趣偏好（Interests） | 六类标签：`咖啡与甜品`、`历史文化`、`城市摄影`、`独立书店`、`公园与绿地`、`本地特色`。既用于打分选点，也用于解释推荐理由。 | 路线规划 | 推荐理由、主题 |
| 出行方式（Transport） | `全程步行`、`步行 + 地铁`、`步行 + 共享单车`。当前仅作为条件记录与展示，未参与路径计算。 | 路线规划 | 规划条件 |
| 预算区间（budget） | 全程消费的估算下限与上限（元），由各站消费区间累加；与会话中用户设定的「预算上限」（`budgetMax`）是两个不同的东西。 | 路线规划 | 预算上限、估算值 |
| 预算上限（budgetMax） | 用户在高级筛选里填写的「预算范围（元）」，留空表示未指定，界面显示「未指定」且不替用户认定预算。 | 路线规划 | 预算区间 |
| 推荐理由（reason / explainPlace） | 每个地点「为什么被选中、为什么排在这个位置」的说明。分两层：地点固有理由 `reason` + 按当次条件生成的动态理由 `explainPlace()`。 | 路线规划 | 兴趣偏好、路线节点 |
| 冲突（Conflict） | 路线安排与用户约束不一致的状态，目前分「时间预算不足」「预算可能超出」两类。冲突必须给可执行选项，不允许静默丢弃需求。 | 路线规划 | 可执行选项、规划条件 |
| 可执行选项（options） | 冲突发生时给用户的候选动作，如「减少一个地点」「把节奏调整为轻松」「去掉最贵的一站」「保留，我自己控制」。 | 路线规划 | 冲突 |
| 顺序已手动调整（orderDirty） | 用户拖拽或上移/下移改变节点顺序后的状态标记。此状态下距离与时间**不重新计算**，界面必须明确提示。 | 路线规划 | 步行耗时、行程时间线 |
| 示意地图（SVG Map） | 自绘的街区示意图，含手绘水系、绿地、城墙与道路纹理，**不含真实经纬度**，不能用于导航。当前默认地图实现（`provider: 'svg'`）。 | 地图 | 真实地图、估算值 |
| 真实地图（Real Map） | 通过适配器接入的高德 / 腾讯 / Leaflet 等真实地图服务，需要地点具备真实经纬度。当前未启用。 | 地图 | 示意地图、适配器 |
| 演示模式（Mock） | AI 与地图能力的本地模拟状态。`agent.mode === 'mock'` 时界面显示「演示模式 · 本地规则模拟」，不得暗示已接入大模型。 | AI 能力 | 已连接、降级 |
| 已连接（Remote） | `agent.mode === 'remote'` 且配置了 endpoint 或自定义请求函数时的状态，界面显示「已连接智能体服务」。 | AI 能力 | 演示模式、降级 |
| 降级（Fallback / degraded） | 远程服务失败后回退到本地规则模拟的状态，结果带 `degraded: true`，界面必须提示「已切换为本地模拟」。 | AI 能力 | 演示模式、已连接 |
| 估算值 | 所有时长、距离、费用字段的属性：由示意坐标与预设系数计算得出，不是实测或实时数据。界面必须标注。 | 全局 | 信息待确认、免责文案 |
| 信息待确认 | 缺失或未核实数据的统一占位文案，当前用于全部地点的营业时间（`hours: null`）。不得用编造值替代。 | 全局 | 估算值、免责文案 |
| 免责文案（DISCLAIMER） | 统一出口的四条数据说明（示例数据 / 估算值 / 营业信息待确认 / 示意地图），供各页面复用，避免口径不一致。 | 全局 | 估算值、信息待确认 |
| 收藏 | 用户标记喜欢的路线或地点，当前仅保存在会话内存中（`storage.favorites: 'memory'`），刷新即清空。 | 我的收藏 | 收藏路线、收藏地点 |
| 城市就绪（ready） | 某城市是否具备完整示例数据的标记。当前仅南京为 `true`，其余四城为「筹备中」，切换时给出提示。 | 全局 | 精选路线、地点 |

## 易混词辨析

| 不要混用 | 正确用法 |
| --- | --- |
| 路线 / 行程 / 计划 | 统一「路线」；「行程时间线」是组件名，不是业务对象名 |
| 地点 / 景点 / POI | 统一「地点」；「POI」只出现在技术文档与代码注释中 |
| 预算区间 / 预算上限 | 前者是路线估算结果，后者是用户设定的条件；写文档时必须区分 |
| 估算值 / 实际值 / 实时 | 本产品只有「估算值」，禁止使用「实际」「实时」 |
| 演示模式 / 测试环境 | 界面统一说「演示模式」，不说「测试环境」「debug 模式」 |
| 精选路线 / 推荐路线 | 统一「精选路线」（人工策划）；AI 生成的结果叫「AI 规划的路线」，两者不可混称 |
